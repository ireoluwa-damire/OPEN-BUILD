# Two-day feature and usability demo

Disciplines: Music and Fashion Design & Tailoring, chosen by the project owner. This tests a product, not two-day mastery.

## Day 1 — first use and setup

1. Give a new tester the app without explaining where to tap. Check whether subject choice and assessment scope are clear.
2. Enter a chosen goal. Try independent, hinted, skipped, and incorrect answers; hints must not count as independent knowledge.
3. Leave midway and resume. First recorded baseline answers must remain unchanged.
4. Try a lesson and a real small project task. Check feedback and prerequisite locks.
5. Switch disciplines and return. Goals, answers, and project steps must stay separate.
6. Review model size, source, and RAM guidance. Download the small Qwen model, pause/resume it, and verify that incomplete files cannot generate answers.
7. Request a local note. Record model name, time to answer, relevance, and errors. A download alone is not a successful inference test.

## Day 2 — return, follow-up, offline, recovery

1. Return to the same discipline. Try the new-example check. Compare follow-up evidence and effort without overwriting the original baseline.
2. Check the early-test label if less than 24 hours have passed. Do not call it 24-hour retention or stable learning speed.
3. After a verified model download, the tester can turn connectivity off and request another note. Exercises and generation should work; publisher links need connectivity.
4. Cancel generation, retry, select another downloaded model, and remove a model. Try a compatible imported GGUF if available. Check graceful failure for a damaged file or low storage.
5. Save navigation ease, question clarity, optional coach usefulness, and a concrete issue note. Confirm feedback survives reopening and stays local.
6. Try reduced motion, large text, screen-reader labels, keyboard-covered forms, and small-screen scrolling. Record heat, battery concerns, confusing statuses, or frame drops without inventing benchmark results.

## Evidence and release decision

Record the task, discipline, device, build, expected/actual result, connectivity state, and reproduction steps. Keep synthetic developer answers separate from real learner data. Automated flow tests use an in-memory preference store; the native model test uses a synthetic prompt.

Minimum demo criteria: both subjects save and resume; local-file inference is demonstrated; failures preserve grading and progress; actions have understandable feedback; limitations are visible. A second model benchmark, audio assessment, automatic garment inspection, and a full animated cast are outside the demo.

## Mascot handoff

Choose your original character before making variants. Build one base rig with modular expressions and props. Make the ten P0 states in the animation brief, then test one export on Android before producing the rest. Motion must not delay answers, cancellation, or navigation.
